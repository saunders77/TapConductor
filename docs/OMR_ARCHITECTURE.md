# Optical music recognition architecture

## Supported workflow

Optical music recognition is implemented for 64-bit Windows desktop builds only. A release
installer contains TapConductor and a pinned Audiveris 5.11.0 application image with its private
Java runtime, native OCR dependencies, and vetted Tesseract language data. No system Java or
separate Audiveris installation is required.

```text
scanned PDF
    |
    |  child process: Audiveris -batch -transcribe -save -export
    v
temporary .omr + preliminary .mxl
    |
    |  Windows save dialog
    v
<chosen-name>.omr + <chosen-name>.mxl
    |
    |  validate/import in Rust; render MusicXML with OSMD
    v
TapConductor performance project

Review recognition
    |
    |  child process: Audiveris GUI opens <chosen-name>.omr
    v
native image-level correction
    |
    |  Audiveris plugin: Send to TapConductor
    v
one-shot TapConductor callback -> private inbox
    |
    |  validate, replace chosen .mxl, reparse, refresh
    v
running TapConductor project
```

The initial batch command writes into an application-local staging directory. TapConductor does not
consider recognition complete unless Audiveris exits successfully and exactly one `.omr` and one
MusicXML export can be found. The save step copies both artifacts to the user's chosen folder. An
existing same-named `.omr` is never overwritten implicitly.

The `.omr` is the durable recognition project and must be kept. Audiveris documents MusicXML export
as lossy: `.omr` can regenerate MusicXML, but MusicXML cannot reconstruct the image evidence and OMR
editing state. Reopening a saved `.mxl` in TapConductor re-associates a same-named sibling `.omr` and
restores **Review recognition**.

## Process and correction boundaries

Audiveris is never linked, loaded as a library, or hosted in the Rust process. TapConductor uses two
documented public integration surfaces:

- Audiveris's command-line batch interface for transcription, `.omr` saving, and MusicXML export.
- Audiveris's `plugins.xml` external-program interface for returning an up-to-date corrected export.

TapConductor gives Audiveris a private `%APPDATA%` root. This keeps the generated plugin and bundled
OCR language configuration separate from a user's independent Audiveris installation. The plugin
launches the TapConductor executable with callback-only arguments; that short-lived process copies
the exported file into a unique inbox and exits without creating a WebView or audio engine. The
running TapConductor process polls only its current inbox, validates the result with the normal Rust
MusicXML importer, copies it to the user-selected `.mxl`, and rebuilds the score/performance state.

OSMD is a rendering and hit-testing layer. It does not correct recognition, change Audiveris's OMR
model, or become the source of image-level truth. Full correction remains in the native Audiveris
editor. A future TapConductor feature may correct a deliberately limited set of performance-relevant
MusicXML semantics after export, but such edits would not replace correction of the `.omr` project.

## Failure and data rules

- PDF input is capped at 512 MiB. Callback exports are capped at 128 MiB and must use a MusicXML
  extension.
- Batch failures surface Audiveris's bounded output and do not install a partial project.
- Multiple MusicXML exports are rejected for now; one PDF must produce one score export.
- A returned export is parsed before the selected `.mxl` is replaced. Invalid returned files are
  quarantined in the private inbox and the currently loaded score is preserved.
- Recognition and correction do no network I/O in TapConductor. Audiveris itself runs locally.
- The callback inbox transports score contents on the local filesystem and is scoped to the current
  Windows user/application-data directory.

## Installer and license boundary

The Tauri MSI/NSIS resource payload includes `sidecars/audiveris/`. Release inputs are generated by
`tools/stage-audiveris.ps1`; `tools/verify-audiveris-bundle.ps1` blocks `npm run tauri:build` unless
all of these are present:

1. the pinned Audiveris 5.11.0 Windows application image;
2. its private Java runtime;
3. at least vetted English Tesseract trained data;
4. the exact corresponding-source archive; and
5. a SHA-256 inventory manifest.

Audiveris is AGPLv3 software and remains an identifiable, separately executable work in the
installer aggregation. TapConductor is GPL-3.0-only. Distribution must preserve Audiveris's license
and notices and provide its complete corresponding source; this repository's release process
chooses to include that exact source archive in the installer rather than rely only on a download
link. `THIRD_PARTY_NOTICES.md` records the component and source locations. Release maintainers must
still audit the official Audiveris image, Java runtime, native OCR libraries, trained-data licenses,
and source archive for each pinned update.

This architecture description records the project's compliance design; it is not legal advice.

## Platform scope

The OMR integration is not compiled as an in-process mobile capability and is not supported on
iOS/iPadOS. Those platforms cannot select PDF for this flow and do not bundle Audiveris, Java, or
Tesseract. Desktop support beyond Windows can be considered later only with equivalent packaging,
process, editor, callback, and license verification.
